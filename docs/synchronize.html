Synchronize

Compare a site with its Remote server, see every file that differs, choose, and only then move anything.

The dialog

Synchronize... asks the questions of Dreamweaver's Synchronize dialog, each answer preselected from the last time:

  1. What to synchronize: the entire site, or the files chosen in the Explorer. This question appears only when it started from an Explorer selection.
  2. Which way: Put files from a time range, Put newer files to remote, Get newer files from remote, or Get and put newer files. The first time, the list opens on Put newer files to remote.
  3. Files only on the other side: keep them, or delete them, worded for the direction, such as Delete remote files not on local drive. After Put files from a time range, the range is asked here instead.

The extension then compares both sides, with progress and a Cancel button. Unchanged files are counted, never listed; if nothing differs, a message says the site is in sync, and what the comparison found in sync is saved, so the next one does not work it out again.

The files of a time range

Put files from a time range puts only the files you worked on lately, such as the pages edited today, without comparing the rest of the site. Its next question is a box that asks Put files created or modified in the last, and holds 1d, or the range you gave last time for the site. Press Enter to take it, or type another. An empty box shows 1d or 24h, and an empty answer means 1d.

A range is a number and one unit, in lower case, with nothing between them:

Units of a time range
UnitExampleMeans
m, minutes90mThe last 90 minutes
h, hours24hThe last 24 hours
d, days2dThe last 2 days
w, weeks1wThe last week

The number can have a decimal part, such as 1.5h. Anything else, such as 2D or 2 d, is refused under the box with the form a range takes.

  • A file counts when it was created or last modified within the range, by this computer's clock and the dates its file system keeps for it. A file copied into the site counts from the moment it arrived, whatever its modification time.
  • A file open with unsaved changes counts by its time on disk, and the server gets the copy on disk. Save it first.
  • Only those files are compared, and only they are looked up on the server, as single files, several at a time. A short range in a large site is quick; when most of the site is recent, Put newer files to remote is quicker.
  • The range applies to the entire site, or to the files chosen in the Explorer when the dialog asked.
  • The preview holds only those files, titled for the range, such as My Site and Production: Put files from the last 2 days. It never lists a delete, a Get, or a file only the server has. A recent file that also changed on the server waits for a decision, and cloaking, the sensitive-file guard and Restricted Mode apply as in any synchronization.
  • With no recent file, a message says so, such as No file of "My Site" was created or modified in the last 2 days., and nothing connects. When every recent file is already the same on the server, the message says how many were compared, such as Nothing from the last 2 days needs putting to Production. 3 files compared.

The command line does the same with sync-servers sync --put recent --range 2d.

The Sync Preview

The preview groups the files by what will happen to each, with a count on every group, decisions first:

Groups of the Sync Preview
GroupHolds
ResolveFiles changed on both sides, or differing with no sync record. They have no checkbox until you choose.
Put, GetFiles that move to or from the server, checked.
Delete remote, Delete localFiles the delete option removes. Files never synchronized before start unchecked.
GuardedSensitive files such as .env, unchecked until you check them.
SkipFiles you chose to skip or mark as synchronized.
ErrorsNames that cannot be used on this system, case twins and links, which never move.

The view's heading names the site, the server and the direction, or the time range; its description gives the summary, such as Files: 36 will be updated, 169 will be skipped, 2 need a decision. The setting syncServers.preview.groupBy groups by folder instead.

Choosing for a file

A file under Resolve offers, inline and in its context menu:

  • Use Local: put the local copy.
  • Use Remote: get the server's copy.
  • Skip: leave both copies this time.
  • Compare with Remote: see both copies side by side.
  • Mark Synchronized: record both copies as in step without moving either.

Choosing moves the row to that group, checked. Any row can take the actions its copies allow, including Delete on Server and Delete Local File. Several rows can be chosen at once, and while a preview waits every action is also in the Command Palette, acting on the rows chosen in the view.

Running it

Synchronize Checked Files in the preview's title bar runs the checked rows. Check All, Uncheck All and Close Preview sit beside it.

  • With syncServers.confirmDeletes on, deletes are listed and confirmed first.
  • Deleting more than the site's delete limit, 50 files or 25 % of a side by default, needs the count typed back.
  • Mirroring from an empty folder is refused, as are deletes at the top of a server unless the server allows them.
  • Each file is checked again just before it moves; one that changed since the preview is skipped and reported.
  • Progress shows in a notification and in the status bar, such as My Site: 12 of 37 files, and Cancel stops between files.

A notification reports the result, such as Synchronized 36 files. 1 failed. 169 skipped. A clean run closes the preview; a run with failures keeps them in the view with their reasons, and the status bar warns until you close it.

Dreamweaver's synchronization records

A site with Dreamweaver sync files on reads and updates the records Dreamweaver keeps in each folder as _notes/dwsync.xml, so a site synchronized with Dreamweaver is in sync from its first preview, and both programs go on agreeing:

  • A file both sides have is in sync when both copies are as its entry says. With no record of the extension's own, one copy as the entry says means the other side changed, so a file Dreamweaver put between two synchronizations is not a conflict.
  • A file that is missing on one side is never judged by an entry, so its delete stays unchecked. An entry never lifts cloaking or the sensitive-file guard either.
  • Each transfer writes the entry Dreamweaver would have written, and a delete removes it. The entries of other servers, and anything in an entry the extension does not know, stay as they were.
  • The records are used only once the way Dreamweaver reads the server's clock is known. The first synchronization of the whole site learns it, from at least three files whose local copy is the one Dreamweaver recorded. Until then the in-sync message says the records are not used yet, and why.
  • A comparison with nothing to run still saves what it found in sync, and the in-sync message says how many files the records showed in sync, such as Dreamweaver's records: 204 files in sync. Later comparisons work from the extension's own records.

The extension's own records stay the ones it trusts, so removing a _notes folder loses nothing here, and turning the setting off deletes nothing. _notes/dwsync.xml itself is never synchronized. Reset Sync Information can remove the server's entries too: see Commands.

Compare with Remote

Compare with Remote fetches the server's copy into a read-only editor beside the local file, in VS Code's diff editor. For a binary or very large file it shows both copies' sizes, times and SHA-256 hashes, and says whether they match. The server's copy is held in memory only while its editor is open.

Put and Get

Put and Get move the file open in the editor, the files chosen in the Explorer or the Remote Files view, or, from the Sites view, a whole site after a question. They go through the same plan and guards as Synchronize: a file that needs a decision, a held-back file or a delete opens the Sync Preview instead of moving, and Put asks to save open files with unsaved changes first.
